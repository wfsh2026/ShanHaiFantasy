# 宗门大比总策划案

## 1. 文档信息

- 文档名称：宗门大比总策划案
- 文档路径：`Assets/Project/ProjectPrompt/宗门大比总策划案.md`
- 版本号：V4
- 状态：A 组最小循环已成立，B 组内容原型已落地，当前进入 C 组体验返修阶段
- 负责角色：策划
- 更新时间：2026-03-30
- 对应项目/版本阶段：首版最小循环原型 + 体验返修阶段

## 2. 项目/版本目标

- 本阶段要解决的问题：
  - 宗门大比能否跑通一局真实多人对局
  - 单主角修仙构筑是否能形成最小可玩体验
  - 房间、开局初始化、回合循环、淘汰结局是否能稳定串起来
  - 当前原型能否从“验证流程”提升为“玩家可理解的玩法”
- 本阶段核心目标：
  - 先成立最小循环
  - 再把最小循环返修成首版玩法原型
- 本阶段预期结果：
  - 玩家可以从房间进入单局
  - 每名参与者拥有本局唯一主角
  - 每回合存在战斗、结果、成长、布阵确认
  - 玩家能看懂为什么赢、为什么输、这次养成改变了什么

## 3. 游戏核心定位

- 题材与世界观定位：
  - 修仙题材
  - 宗门大比
  - 多方同局竞争
- 核心卖点：
  - 单主角修仙构筑
  - 多人房间 + AI 补位
  - 自动战斗 + 多轮淘汰
- 差异化方向：
  - 不做多单位自走棋
  - 不做大而全局外养成
  - 强调单局内的主角成长与修仙味

## 4. 目标玩家与核心乐趣

- 目标玩家：
  - 喜欢修仙题材
  - 喜欢构筑与成长选择
  - 能接受自动战斗与多轮对局
- 核心乐趣点：
  - 选主角时有方向差异
  - 回合内成长能持续改变战斗结果
  - 在淘汰压力下做构筑取舍
- 玩家持续游玩的驱动力：
  - 每局不同主角模板与宗门环境
  - 五条养成线组合差异
  - 多人对局与 AI 对手带来的不同局面

## 5. 核心玩法循环

- 玩家进入目标：
  - 创建或加入房间
- 玩家执行行为：
  - 从 8 人房间进入对局
  - 选择本局唯一主角
  - 观看宗门环境揭示
  - 进入回合循环并做成长选择
- 玩家获得反馈：
  - 战斗结果
  - 主角成长变化
  - 气运变化
  - 淘汰与排名变化
- 玩家获得资源/成长：
  - 物 / 法 / 财 / 伴 / 地五条线
  - 主选项池与次选择池
- 玩家进入下一轮循环：
  - 继续战斗
  - 直到只剩 1 名参与者

## 6. 整体游戏流程

- 新手阶段流程：
  - 进入房间
  - 创建 / 加入
  - 由房主开始
- 核心成长流程：
  - 房间开始后进入开局初始化
  - 主角三选一
  - 宗门环境揭示
  - 回合主循环
- 中期扩展流程：
  - 五大模块深化
  - 剑修职业样板深化
- 当前返修流程：
  - 战斗结果反馈返修
  - 养成承载真实生效返修
  - 正式界面与调试隔离返修
  - AI 决策修正

## 7. 主要系统总览

- 房间系统：
  - 负责 8 槽位房间、邀请码、房主开始、AI 补位
  - 以 `A1_房间与开局准备_策划规格_V1.md` 为准
- 开局初始化系统：
  - 负责主角三选一、AI 自动选主角、主角初始化、宗门环境揭示
  - 对应 A2
- 回合系统：
  - 固定为 `Battle -> BattleResult -> Cultivation -> FormationConfirm`
- 战斗系统：
  - 负责单主角 1v1 自动战斗与结果反馈
- 五大养成系统：
  - 负责物、法、财、伴、地五线承载与成长
- 联机与同步系统：
  - 服务端权威
  - Room / Battle 两段主链

## 8. 系统关系说明

- 房间系统负责把参与者送入单局
- A2 负责把房间参与者转成可进入回合的主角与环境状态
- 回合系统负责承载战斗、成长与布阵确认
- 战斗结果驱动气运、淘汰与结局
- 五大养成线服务于单主角成长，不独立脱离主角体系
- 联机系统负责同步房间状态、对局状态与服务端权威结果

## 9. 各阶段体验目标

- 新手期体验目标：
  - 快速进房
  - 看懂房间参与者结构
  - 顺利进入单局
- 中期体验目标：
  - 主角选择有差异
  - 宗门环境对本局有明确提示
  - 回合循环稳定可读
- 当前返修体验目标：
  - 战斗结果可读、可复盘
  - 养成变化可感知、可解释
  - 玩家路径不再混入验证与调试表达
- 长线体验目标：
  - 职业样板、AI 对手、内容池持续扩展

## 10. 当前版本范围

- 本版已完成：
  - A 组最小循环 7 个 TASK
  - 房间到开局初始化到回合循环的完整通路
  - 单主角、单环境、单局淘汰的基础原型
- 本轮返修必做：
  - C 组体验返修 5 个 TASK
  - 把当前“能跑通的验证原型”收紧为“玩家能理解、能选择、能复盘的首版玩法原型”
  - 修正战斗表现、养成承载、正式界面、AI 决策和内容差异这 5 个当前体验断点
- 后续再做：
  - 更大体量的职业扩展
  - 多环境、多职业、多局外成长
  - 长线数值与内容池扩充
- 明确不做：
  - Ready 机制
  - 匹配系统
  - 重连与断线恢复
  - 多房间并存
  - 多单位阵容
  - 复杂演出与局外系统

  - 功能目标：让五线承载和养成落点不再只是展示与加数值，而是明确影响后续战斗结果
  - 核心流程：养成选择 -> 承载落位 -> 权重/效果入战斗 -> 战斗结果体现

  - 优先级：P0

  - 核心流程：AI 主角选择 -> AI 养成选择 -> AI 站位确认 -> 单局行为差异
  - 目标体验：玩家面对 AI 时能看到不同的对手倾向
  - 优先级：P0
  - 前置依赖：B5
  - 输出文档：`C4_AI站位与对局决策修正_策划规格_V1.md`
- C5：内容池扩容与职业差异强化
  - 功能目标：补足首版内容深度，让主角模板、养成项和职业体验不再高重复
  - 核心流程：扩主角模板池 -> 扩主选项池 -> 强化剑修模板差异 -> 形成多局差异
  - 目标体验：连续开多局时，玩家仍能感到方向差异和取舍空间
  - 优先级：P1
  - 前置依赖：B2-B4
  - 输出文档：`C5_内容池扩容与职业差异强化_策划规格_V1.md`

## 13. 待确认项与风险

- 待确认问题：
  - 首版战斗反馈里优先展示哪些原因摘要最有价值
  - 首版要强化哪些“承载变化 -> 战斗反馈”映射
  - C3 中正式玩家界面是否保留极简帮助入口
- 风险点：
  - 当前 B 组实现更接近“验证原型”而不是“正式玩法原型”，若直接继续扩内容，会把体验缺口一并放大
  - 当前战斗主链仍以总分结算为主，若不补足回合表现和结果反馈，玩家难以理解构筑影响
  - 当前五线承载主要影响展示和基础加数值，若不补足承载到战斗的强反馈，构筑乐趣会持续偏弱
  - 当前正式玩家路径中仍混入验证面板与调试入口，若不隔离，体验会持续像测试工具而不是游戏
  - 当前 AI 站位与阵眼联动存在实现偏差，若不修正，B5 的“AI 有差异决策”实际上无法成立
- 影响范围：
  - BattleMode
  - NetworkSyncBattle
  - UIManager
  - 测试场景与调试入口
- 建议下一步：
  - 先按 C1-C4 四个 P0 返修 TASK 推进
  - 由主程逐个补齐对应开发文档
  - 程序按返修顺序进入实现，代码审核员继续闭环把关
