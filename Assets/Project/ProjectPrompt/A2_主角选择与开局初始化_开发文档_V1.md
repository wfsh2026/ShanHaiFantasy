  - 是否新增：否，扩展现有模块
- 模块名称：ClientBattleModeLogic 扩展
  - 模块类型：Mode Logic
  - 模块职责：处理客户端阶段切换、UI 打开关闭、选择提交与快照接收

  - 模块类型：Mode Logic
  - 模块职责：生成候选、处理锁定、AI 自动选择、环境抽取、推进到回合

## 9. 数据流与状态流

- `Config`
  - 主角模板池配置
  - 宗门环境配置
  - AI 默认选主角权重
- `Data`
  - 参与者候选列表
  - 每名参与者已选主角模板
  - 主角是否锁定
  - 宗门环境结果
  - 当前 `mainState = HeroSelect / SectReveal`
- `Logic`
  - 服务端生成 3 选 1 候选
  - 服务端处理真人提交
  - 服务端执行 AI 自动选择与超时兜底
  - 服务端完成主角初始化和环境抽取
- `UI`
  - 主角选择卡片展示
  - 其他参与者锁定进度展示
  - 宗门环境揭示展示

同时说明：

- 关键输入来源：
  - A1 锁定后的房间参与者快照
  - 主角模板配置
  - 宗门环境配置
- 关键状态变化：
  - `MatchInit -> HeroSelect -> SectReveal -> RoundLoop`
  - `participant.hasLockedHero = false -> true`
  - `battle state` 写入主角选择结果和环境结果
- 关键输出去向：
  - A3 / 后续回合读取初始化后的主角状态
  - 客户端 UI 展示同步结果

## 11. 关键流程

1. 入口
   - A1 房间开始后切入 `BattleTestScene`
   - `BattleMode` 以房间快照初始化
2. 模块调用顺序
   - `ServerBattleModeLogic` 读取房间快照
   - 进入 `HeroSelect`
   - 服务端生成候选并广播
   - 客户端 UI 展示候选
   - 真人提交选择，AI 自动选择
   - 服务端写入锁定结果
   - 服务端初始化主角状态
   - 服务端抽取宗门环境并广播
   - 进入 `SectReveal`
   - 完成揭示后推进到 `RoundLoop`
3. 状态变化
   - `mainState` 从 `MatchInit` 进入 `HeroSelect`
   - 全员锁定后进入 `SectReveal`
   - 揭示完成后进入 `RoundLoop`
4. 网络交互
   - 新增 Battle 选择提交命令
   - 新增 Battle 开局状态 RPC 或扩展现有快照字段
   - 继续沿用 Battle 快照广播
5. 结果回写
   - `BattleModeData` 保留本局主角与环境初始化结果
   - 后续回合系统直接读当前 Battle 状态
