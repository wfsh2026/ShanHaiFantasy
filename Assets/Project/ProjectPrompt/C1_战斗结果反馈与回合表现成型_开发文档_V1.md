## 5. 功能目标

- 解决当前战斗阶段“直接算输赢，玩家不知道发生了什么”的问题
- 把每轮战斗收成玩家能看懂对手、站位、阵眼命中与关键结果原因的最小回合表现
- 让 `Battle`、`BattleResult`、`Cultivation` 三个阶段形成连续体验
- 不追求：
  - 复杂战斗演出
  - 逐帧技能播报系统
  - 独立重做新的 Battle 模式

## 9. 数据流与状态流

- `Config`
  - 本任务不新增正式配置资产
- `Data`
  - 新增或补齐“本轮结果原因摘要”相关字段
  - 明确“上一轮结果摘要”作为养成阶段稳定入口
  - 保持 `BattleMatchList` 为服务端权威结果源
- `Logic`
  - 服务端在结算战斗时同时生成：
    - 胜负结论
    - 气运变化
    - 轮空说明
    - 关键结果原因摘要
  - 客户端不推导结果原因，只展示同步结果
- `UI`
  - `Battle` 阶段展示本轮对手、站位、阵眼、趋势摘要
  - `BattleResult` 阶段展示本轮结果、气运变化、关键原因
  - `Cultivation` 阶段保留上一轮结果回看入口

## 10. Client / Server 责任分配

- 客户端负责：
  - 展示 `Battle` / `BattleResult` / `Cultivation` 三阶段的结果信息
  - 读取服务端结果快照，不自行推导胜负原因
- 服务端负责：
  - 结算战斗
  - 生成可读的结果原因摘要
  - 区分轮空、胜利、失败、平局
  - 把结果写入 battle 快照并广播
- 需要同步的状态：
  - 本轮对手信息
  - 本轮阵眼命中信息
  - 本轮结果原因摘要
  - 本轮气运变化与淘汰状态
- 同步方式：
  - 继续通过 `NetworkSyncBattleStateRpc` 扩展字段承载
- 不能越界的点：
  - UI 不直接拼接本地假原因
  - 客户端不直接改写战斗结算结果

## 11. 关键流程

1. 进入 `Battle` 阶段
2. 服务端基于当前参与者、站位、阵眼与成长结果完成一次结算
3. 服务端把结果写入 `BattleMatchList` 和本地玩家最近结果字段，同时生成“本轮结果原因摘要”
4. `NetworkSyncBattleStateRpc` 广播结果快照
5. 客户端 `BattleA2PanelController` 在 `Battle` 阶段显示本轮对战摘要
6. 进入 `BattleResult` 阶段后显示结果结论、气运变化与关键原因
7. 进入 `Cultivation` 阶段时保留上一轮摘要，给玩家后续选择上下文

### 异常与回退流程

- 若本轮轮空：
  - 服务端明确写入轮空标识与轮空摘要
  - UI 不显示空白对手
- 若本轮没有可读原因：
  - 服务端必须至少给出“阵眼 / 站位 / 养成”中的最小默认原因摘要
  - 不允许只返回空字符串
