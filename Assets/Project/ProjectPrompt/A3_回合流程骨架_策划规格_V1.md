# A3_回合流程骨架_策划规格_V1

## 1. Task 基本信息

- Task ID：A3
- Task 名称：回合流程骨架
- 所属总策划案：`宗门大比总策划案.md`
- 优先级：P0
- 前置依赖：A1 房间与开局准备、A2 主角选择与开局初始化

## 2. 功能目标

- 该 Task 要解决的问题：
  - A2 结束后虽然已经能进入 `RoundLoop`，但当前回合推进仍是临时 stub，边界和后续 A4/A5/A6 混在一起。
  - 当前缺少“单局按固定回合结构稳定推进”的正式骨架定义。
- 该 Task 的核心目标：
  - 建立一局游戏进入 `RoundLoop` 后的标准回合结构。
  - 固定回合阶段顺序与推进规则。
  - 让系统能从第 1 回合稳定推进到下一回合，而不乱序、不跳阶段。
- 该 Task 完成后的预期结果：
  - 单局可稳定进入第 1 回合。
  - 每回合固定包含 `Battle -> BattleResult -> Cultivation -> FormationConfirm` 四个阶段。
  - 当前回合结束后可进入下一回合。

## 3. 玩家体验目标

- 玩家在该功能中应感受到什么：
  - 对局开始后拥有明确的回合节奏，而不是只有开局展示后立即跳到不可感知的自动处理。
  - 每回合都有可识别的阶段切换感。
  - 整体流程有“在推进一局修仙淘汰赛”的稳定秩序感。
- 该功能想强化什么乐趣：
  - 回合节奏清晰。
  - 阶段顺序可预期。
  - 为后续战斗、养成、布阵内容提供稳定承载框架。
- 该功能要避免什么负面体验：
  - 阶段切换顺序混乱。
  - 刚进入 `RoundLoop` 就直接结算或淘汰，导致骨架与内容耦合。
  - 玩家无法判断当前回合到了哪一个阶段。

## 4. 核心规则

#### 4.1 进入 A3 的规则
- A2 完成后，所有参与者已完成主角锁定与宗门环境揭示。
- 系统正式进入 `RoundLoop`。
- `RoundLoop` 是战斗主链内的正式状态，不单独开平行模式。

#### 4.2 当前固定回合阶段
- 每回合固定包含以下四个阶段：
  - `Battle`
  - `BattleResult`
  - `Cultivation`
  - `FormationConfirm`
- 首版只要求固定顺序和稳定推进，不要求每个阶段内具备完整玩法内容。

#### 4.3 阶段推进规则
- 单局进入 `RoundLoop` 后，默认从第 `1` 回合的 `Battle` 阶段开始。
- 当前阶段完成后，必须按固定顺序进入下一阶段：
  - `Battle -> BattleResult`
  - `BattleResult -> Cultivation`
  - `Cultivation -> FormationConfirm`
  - `FormationConfirm -> 下一回合 Battle`
- 当前版本不允许跳阶段，不允许反向回退阶段。

#### 4.4 回合递进规则
- 只有当 `FormationConfirm` 阶段完成时，当前回合才视为结束。
- 当前回合结束后，回合数 `+1`，并进入下一回合的 `Battle` 阶段。
- 当前版本首要保证“回合骨架稳定递进”，不要求在 A3 内决定整局何时结束。

#### 4.5 阶段内最小承载规则
- `Battle`：只承载“进入战斗阶段”的最小状态，不要求 A3 内实现正式战斗结果逻辑。
- `BattleResult`：只承载“战斗结果阶段开始”的最小状态，不要求 A3 内生成完整胜负、扣气运、淘汰。
- `Cultivation`：只承载“进入养成阶段”的最小状态，不要求 A3 内提供正式养成选项。
- `FormationConfirm`：只承载“进入布阵确认阶段”的最小状态，不要求 A3 内提供正式布阵系统。

#### 4.6 A3 与后续 Task 的边界
- A3 不负责正式战斗结果结算，A4 再补。
- A3 不负责扣气运、淘汰、终局，A5 再补。
- A3 不负责正式养成内容与五线样本，A6/A7 再补。
- A3 可以保留最小占位数据与最小验证表现，但不能提前把 A4/A5 的规则写死。

## 5. UI 需求

#### 5.1 UI 目标
- 在 `RoundLoop` 中让玩家和开发者都能识别：
  - 当前是第几回合
  - 当前处于哪一个阶段
  - 当前阶段是否已完成并进入下一阶段

#### 5.2 最小界面构成
- 当前回合编号
- 当前阶段名称
- 四阶段顺序展示
- 当前阶段高亮
- 阶段推进提示

#### 5.3 当前版本要求
- A3 可以沿用现有 Battle 测试 UI 链路补充回合阶段展示。
- A3 不要求单独重做正式美术界面。
- UI 只负责展示回合状态与阶段递进，不负责本地决定阶段推进。

## 6. 流程顺序

#### 6.1 标准流程
1. A2 完成并进入 `RoundLoop`
2. 系统进入第 1 回合 `Battle`
3. 阶段推进到 `BattleResult`
4. 阶段推进到 `Cultivation`
5. 阶段推进到 `FormationConfirm`
6. 当前回合结束
7. 系统进入下一回合 `Battle`

#### 6.2 最小实例流程
1. 房间开始
2. A2 完成
3. 进入第 1 回合 `Battle`
4. 顺序看到四个阶段依次推进
5. 回合数递增到第 2 回合
6. 第 2 回合再次从 `Battle` 开始

## 7. 补充规则

#### 7.1 中断规则
- 当前首版不处理掉线重连恢复。
- 当前首版不处理中途返回房间。
- 若阶段推进依赖完整内容但后续 Task 尚未实现，应使用最小占位推进，不得直接卡死。

#### 7.2 默认处理规则
- 阶段推进可以使用固定停留时长或最小确认条件。
- 当前版本默认采用统一、稳定、可验证的推进方式。
- 当前版本优先保证流程清晰，而不是追求阶段内容丰富。

## 8. 相关系统影响

- 会影响哪些系统：
  - `BattleMode`
  - Battle 测试 UI
  - Battle 测试场景验证入口
  - Battle 网络状态同步
- 对其他系统的输入/输出变化：
  - A2 输出“已进入 RoundLoop”的初始状态给 A3。
  - A3 输出“当前回合编号 + 当前阶段 + 阶段顺序推进结果”给 A4/A5/A6 继续承接。

## 9. 验收标准

- 功能完成的判断标准：
  - 单局可进入 `RoundLoop`
  - 第 1 回合从 `Battle` 开始
  - 四阶段按固定顺序推进
  - `FormationConfirm` 完成后进入下一回合
- 流程正确的判断标准：
  - 不跳阶段
  - 不乱序
  - 不在 A3 内提前触发正式淘汰与终局
- 体验达标的判断标准：
  - 玩家或测试者能看清当前回合与当前阶段
  - 开发测试链能验证至少 2 个回合连续推进

## 10. 不做范围

- 当前 Task 不包含：
  - 正式战斗胜负规则
  - 正式扣气运与淘汰
  - 正式终局结算
  - 正式养成内容
  - 正式布阵系统
- 明确不在本次开发范围内的项：
  - A4 战斗结果定义
  - A5 淘汰与终局规则
  - A6/A7 养成与选项池内容

## 11. 待确认项

- 尚未拍板的问题：
  - 四阶段默认停留时长是否统一
  - 每阶段是否需要额外“玩家确认后继续”的版本分支
- 需要后续确认的规则：
  - A4 接入时 `Battle` 与 `BattleResult` 的最小交接字段
  - A6/A7 接入时 `Cultivation` 与 `FormationConfirm` 的最小承接字段
