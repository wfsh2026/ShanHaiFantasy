# C3：正式养成界面与调试隔离

## 1. Task 基本信息

- Task ID：C3
- Task 名称：正式养成界面与调试隔离
- 所属总策划案：`宗门大比总策划案`
- 优先级：P0
- 前置依赖：B1、B6

## 2. 功能目标

- 解决当前玩家进入对局后仍看到验证文本、验证器和调试心智的问题。
- 让玩家主路径只保留正式玩法界面，让调试入口退回测试场景与开发入口。
- 把当前“测试界面能用”提升为“正式玩家界面可接受”。

## 3. 玩家体验目标

- 玩家进入对局时看到的是主角选择、养成、布阵、结果等正式界面，而不是验证板。
- 玩家不需要理解任何“B1-B6 验证”“Scene Verifier”“QuickSetup”之类的开发语义。
- 调试行为不会再影响正常玩家体验判断。

## 4. 核心规则

### 4.1 正式界面规则
- 玩家主路径中的界面必须围绕玩法流程组织，不允许把验证状态当成主体内容。
- 正式界面中的文案必须使用玩家语义，而不是开发/验证语义。
- 正式界面里不显示调试按钮、验证步骤编号和开发状态标签。

### 4.2 调试隔离规则
- 调试按钮和验证面板只允许出现在测试场景或明确的开发验证入口中。
- 正式玩家路径默认不自动打开调试入口。
- 测试场景仍可保留强制推进和快速验证能力，但要与玩家主路径明确隔离。

### 4.3 信息分层规则
- 主界面优先展示当前阶段最关键的信息。
- 验证信息如果仍需保留，只能放在测试模式、开发模式或额外入口里。

## 5. UI 需求

- 正式主角选择界面
- 正式养成界面
- 正式布阵确认界面
- 正式结果摘要界面
- 测试场景专用调试面板
- 测试场景专用验证摘要

## 6. 流程顺序

### 6.1 正常玩家流程
1. 进入主角选择。
2. 进入环境揭示。
3. 进入回合循环。
4. 在养成与布阵界面完成操作。
5. 全程不看到验证器和调试按钮。

### 6.2 测试流程
1. 进入测试场景。
2. 主动进入调试或验证入口。
3. 使用强制推进与验证能力。

## 7. 验收标准

- 正常玩家路径默认不显示验证器、调试按钮和开发验证文案。
- 测试场景仍能保留强制推进、快速切阶段和验证摘要能力。
- 玩家对当前阶段的理解不依赖任何验证信息。

## 8. 不做范围

- 不做完整美术重做。
- 不做复杂转场演出。

## 9. 待确认项

- 正式玩家路径是否保留极简“帮助/说明”入口。
- 测试场景里的调试入口是否需要再细分为策划验证和程序验证两套模式。
